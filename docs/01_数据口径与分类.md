## 二、「古代类」筛选标准

以**核心吸引物是否为 1912 年以前形成、且至今留存或原址延续的文化遗产**为判定标准。

### 纳入（12 类）

| 类别 | 定义 | 典型 |
|---|---|---|
| 宫殿坛庙 | 皇家宫殿、礼制坛庙、孔庙/祠庙、藩王府 | 故宫、天坛、三孔、靖江王城 |
| 古典园林 | 皇家与私家园林、王府花园 | 颐和园、避暑山庄、苏州园林、恭王府 |
| 古城古镇 | 历史上形成、格局完整的城镇聚落 | 平遥、丽江、喀什、周庄、乌镇 |
| 古村落 | 传统村落、民居建筑群 | 西递宏村、福建土楼、开平碉楼 |
| 宗教寺观 | 佛寺、道观、清真寺、藏传佛教寺院及塔 | 少林寺、布达拉宫、大昭寺、塔尔寺、崇圣寺三塔 |
| 历史名山 | 以宗教、封禅、人文胜迹为核心的山岳（含文化/双遗产山岳） | 泰山、五台山、武当山、峨眉山、嵩山 |
| 石窟石刻 | 石窟寺、摩崖造像、碑林石刻 | 云冈、龙门、大足、麦积山 |
| 古遗址 | 考古遗址、城址、窑址、史前遗址 | 殷墟、兵马俑、大明宫、水洞沟 |
| 陵寝墓葬 | 帝王陵、名人墓及墓葬群 | 明十三陵、清东陵、乾陵、明显陵 |
| 关隘长城 | 长城本体、关隘、烽燧及线性防御遗存 | 八达岭、嘉峪关、山海关、剑门关 |
| 历史街区 | 成片历史地段、近代国际社区 | 三坊七巷、鼓浪屿 |
| 复合人文 | 名楼、文化景观、城垣+碑林等多要素复合景区 | 西湖、西安城墙碑林、黄鹤楼、夫子庙秦淮 |

### 排除

- 纯自然景观：湖泊、草原、海滩、溶洞、丹霞、雪山、森林公园、地质公园（如喀纳斯、沙坡头、黄果树）。
- 现代主题乐园与度假区：长隆、迪士尼、方特、环球恐龙城、长影世纪城。
- 现代影视城/仿古主题园：横店影视城、无锡三国水浒城、镇北堡西部影城；**清明上河园等 1990 年后新建仿古园区**暂不纳入，如需表达宋代文化，另设「仿古文化园」标签。
- 现代城市公园、世博园、现代水利/工业工程：奥林匹克公园、昆明世博园、三峡大坝、红旗渠。
- 红色革命史迹：西柏坡、韶山、井冈山、瑞金、邓小平故里、延安革命纪念地等。该类数量多、主题独立，建议作为**可选第二图层**「近现代史迹」，不与古代主线混淆。

### 灰色地带的处理原则

1. **自然与人文复合山岳**（黄山、庐山、武夷山、泰山、峨眉山、武当山、五台山、普陀山、九华山、龙虎山、青城山、崆峒山）：纳入「历史名山」，`note` 标注遗产类型。
2. **历代名楼的现代复建**（黄鹤楼 1985 年复建、滕王阁 1989 年复建）：纳入「复合人文」，`note` 必须注明复建年代。
3. **清末至民国建筑**（开平碉楼、鼓浪屿、三坊七巷）：纳入，`dynasty` 填「清末至民国」。
4. **跨省共建景区**（黄河壶口瀑布）：按 1 条记录，`province` 填两省区全称、以顿号分隔。
5. 存疑景区逐条在 `note` 中说明判定理由，不做静默取舍。

## 三、字段规范

GeoJSON 要素属性（与 PostGIS 表一一对应，前端使用驼峰、数据库使用蛇形）：

| 字段 | 类型 | 说明 | 示例 |
|---|---|---|---|
| id | int | 唯一编号（建库时按省份顺序分配） | 1 |
| name | string | 官方名称（以文旅部名单为准） | 故宫博物院 |
| province | string | 省级行政区 | 北京市 |
| city | string | 地级市/州/盟 | 北京市 |
| ratingYear | int | 5A 评定年份；复牌景区用 note 标注 | 2007 |
| category | string | 12 类之一 | 宫殿坛庙 |
| dynasty | string | 始建或主体遗存朝代，跨代用顿号/「至」 | 明、清 |
| worldHeritage | bool | 是否世界文化遗产（含文化景观、扩展项目） | true |
| majorSite | bool | 核心遗存是否为全国重点文保单位 | true |
| note | string? | 复建、复合、坐标点等说明 | — |
| coordinates | [lng,lat] | WGS84（EPSG:4326），GeoJSON 标准顺序 | [116.397,39.918] |

## 四、坐标规范

1. **统一 WGS84（EPSG:4326）**，与 OSM、GeoServer 发布坐标系一致；前端由 OpenLayers 转换为 EPSG:3857 显示。
2. 高德/百度/腾讯 POI 为 GCJ-02/BD-09 坐标，**必须先纠偏到 WGS84** 再入库，禁止混用。
3. 点位置定义：景区**核心遗产点/主入口**（如苏州园林取拙政园、福建土楼取承启楼），在 `note` 中注明取值点。
4. 当前样例（47 个）坐标为公开资料整理的近似值，**精度约 0.01°（约 1km）**，正式数据须经天地图地名搜索或 OSM Overpass 核对后替换。
5. 省界面数据使用阿里云 DataV 行政边界（`https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json`）或自然资源部标准地图，落库前统一转 EPSG:4326。

## 五、双时间维度设计

- **ratingYear（评定年份 2007–2024）**：现代管理维度，用于展示 5A 制度推进与景区评定时序。
- **dynasty（朝代）**：古代文化维度，是本项目的**主时间轴**。朝代排序标准：
  先秦（旧石器—夏商周）→ 秦 → 汉 → 魏晋南北朝 → 隋唐 → 宋 → 元 → 明 → 清 → 清末至民国 → 跨代/复建。
- 跨朝代景区以**最早始建朝代**入时间轴，`dynasty` 字段保留完整年代信息。

## 六、后续完整数据整理流程

1. 从 358 家总名单按本标准筛选古代类（预计 150–180 家），形成 `data/works/ancient_5a_full.csv`。
2. 批量地理编码：天地图 Web 服务 API（需 key）或 OSM Overpass 按「名称+城市」查询，输出候选坐标。
3. 人工复核：逐一核对坐标点、类别、朝代、遗产身份。
4. 脚本生成 GeoJSON（`npm run validate-data` 校验）→ PostGIS 导入 → GeoServer 发布。
